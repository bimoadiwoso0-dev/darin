# دارین — سامانه جامع مدیریت کتابخانه

نرم‌افزار مدیریت کتابخانه برای کتابخانه‌های واقعی با ده‌ها هزار جلد کتاب.
کارایی سامانه روی **۱۰۰٬۰۰۰ کتاب و ۱۲۲٬۰۰۰ نسخه فیزیکی** سنجیده شده است.

رابط کاربری کاملاً فارسی و راست‌به‌چپ است، تاریخ‌ها شمسی نمایش داده می‌شوند و
جستجو با نرمال‌سازی فارسی کار می‌کند: «كتابخانه ي مركزي» همان چیزی را پیدا
می‌کند که «کتابخانهٔ مرکزی» پیدا می‌کند.

کتاب را می‌توان **با گفتار** ثبت کرد: میکروفون را روشن کنید و بگویید «عنوان
قلعه حیوانات، نویسنده جورج اورول، ناشر امیرکبیر، سال هزار و سیصد و نود و
نه» — سامانه پیش از اعمال نشان می‌دهد چه چیزی را در کدام فیلد فهمیده است.

## راه‌اندازی برای توسعه

نیازمندی‌ها: **Node.js ≥ 20.10**، **pnpm 9**، **PostgreSQL 16**، و اختیاری **Redis 7**.

```bash
git clone <repo> darin && cd darin
pnpm install

cp .env.example .env
# دو کلید JWT را با دستور زیر بسازید و در .env بگذارید:
openssl rand -base64 48

# پایگاه داده
createdb darin
pnpm db:migrate
pnpm db:seed            # داده سیستمی + داده نمایشی

pnpm dev                # API روی :3001 و رابط کاربری روی :5173
```

سپس `http://localhost:5173` را باز کنید. اولین بار **جادوگر راه‌اندازی** اجرا
می‌شود و حساب مدیر ارشد را می‌سازد — هیچ رمز پیش‌فرضی در کد وجود ندارد.

### داده نمایشی در برابر داده واقعی

`pnpm db:seed` دو بخش دارد که هرگز قاطی نمی‌شوند:

- **داده سیستمی** (مجوزها، نقش‌ها، تنظیمات، قوانین شماره‌گذاری، شعبه پیش‌فرض)
  — همیشه ساخته می‌شود و در Production هم لازم است.
- **داده نمایشی** (کتاب و عضو و امانت ساختگی) — فقط وقتی
  `NODE_ENV !== production` باشد و پایگاه داده خالی باشد.

برای Production فقط بخش سیستمی: `pnpm db:seed -- --core-only`
برای پاک کردن داده نمایشی: `pnpm db:seed -- --purge-demo`

| دستور | کار |
|-------|-----|
| `pnpm dev` | اجرای API و رابط کاربری با بارگذاری مجدد خودکار |

| `pnpm --filter @darin/api perf:measure` | سنجش زمان پاسخ کوئری‌های حیاتی |

## ساختار مخزن

```
apps/
  api/          NestJS + Prisma + PostgreSQL
    prisma/     Schema، مهاجرت‌ها، Seed، ابزار سنجش کارایی
    src/
      common/       فیلتر خطا، نگهبان‌ها، Pipeها، ابزار مشترک
      config/       اعتبارسنجی متغیرهای محیطی
      infrastructure/  Prisma، صف، ذخیره‌سازی، Log
      modules/      ماژول‌های دامنه (کاتالوگ، امانت، اعضا، …)
  web/          React + Vite + Tailwind
    src/
      components/   سیستم طراحی و اجزای مشترک
      pages/        صفحه‌ها، هم‌نام با مسیرها
      lib/          کلاینت API، قالب‌بندی، هوک‌ها
packages/
  shared/       نوع‌ها، Zod Schemaها، ابزار فارسی و تاریخ شمسی
                (تنها منبع حقیقت برای هر دو سمت)
```

جزئیات و دلیل هر انتخاب در [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## پشته فناوری

| لایه | انتخاب | چرا |
|------|--------|-----|
| API | NestJS 10 + TypeScript | ساختار ماژولار روشن، تزریق وابستگی، مناسب رشد |
| ORM | Prisma 7 | مهاجرت‌های نسخه‌دار، ایمنی نوع سرتاسری |
| پایگاه داده | PostgreSQL 16 | جستجوی تمام‌متن، `pg_trgm`، ایندکس جزئی، تراکنش واقعی |
| جستجو | FTS + trigram داخل PostgreSQL | برای این مقیاس، Elasticsearch هزینه نگهداری بی‌دلیل است |
| صف | BullMQ + Redis | کارهای سنگین (Import، پشتیبان، اعلان) خارج از چرخه درخواست |
| رابط کاربری | React 18 + Vite + Tailwind | ساخت سریع، کنترل کامل روی RTL |
| داده سمت کلاینت | TanStack Query | Cache، هم‌زمان‌سازی، تلاش مجدد هوشمند |
| اعتبارسنجی | Zod (مشترک بین API و UI) | یک تعریف، دو مصرف‌کننده |

## کارایی

روی **۱۰۰٬۰۰۰ کتاب · ۱۲۲٬۱۵۲ نسخه · ۱۷٬۹۵۶ امانت** (۲۴۲ مگابایت):

| کوئری | میانه |
|-------|-------|
| یافتن نسخه با بارکد (پرتکرارترین کوئری میز امانت) | ۲.۴ms |
| جستجوی متن فارسی در عنوان | ۳۱.۸ms |
| جستجوی تقریبی با غلط املایی (trigram) | ۱۷۲ms |
| فهرست کتاب‌ها، صفحه اول | ۵.۰ms |
| فهرست کتاب‌ها، صفحه ۲۵۰ (offset ۵۰۰۰) | ۲.۵ms |
| امانت‌های دیرکرددار با اطلاعات عضو و کتاب | ۱۲.۹ms |

بازتولید: `pnpm seed:perf && pnpm --filter @darin/api perf:measure`

## اصولی که در کل پروژه رعایت شده

- **هیچ قابلیت ظاهری نیست.** هر دکمه کار می‌کند: پشتیبان واقعاً `pg_dump`
  می‌زند، خروجی Excel واقعاً فایل می‌سازد، جستجو واقعاً از پایگاه داده
  می‌خواند. هیچ عدد Hard-code شده‌ای در آمار نیست.
- **هیچ رمزی در کد نیست.** حساب مدیر در جادوگر راه‌اندازی ساخته می‌شود.
- **کاربر Stack Trace نمی‌بیند.** پیام خطا فارسی و قابل فهم است؛ جزئیات فنی
  با شناسه درخواست در Log ثبت می‌شود.
- **حذف واقعی نداریم.** رکوردهای حساس بایگانی می‌شوند تا تاریخچه تراکنش‌ها
  از بین نرود.
- **RTL واقعی است،** نه فقط `text-align: right` — کل چیدمان با ویژگی‌های
  منطقی CSS نوشته شده است.
- **تاریخ نمایش و تاریخ ذخیره‌سازی جدا هستند:** نمایش شمسی، ذخیره‌سازی
  `timestamptz` استاندارد.
