# پشتیبان‌گیری و بازیابی

پشتیبان‌گیری در این سامانه **واقعی** است: دکمه پشتیبان‌گیری `pg_dump` اجرا
می‌کند و یک فایل `.sql.gz` با چک‌سام SHA-256 می‌سازد. هیچ شبیه‌سازی یا
فایل نمایشی در کار نیست.

---

## آنچه پشتیبان می‌گیرد

خروجی `pg_dump` کل پایگاه داده است: ساختار جدول‌ها، داده، کلیدهای خارجی،
توالی‌ها (شماره ثبت بعدی)، ایندکس‌ها و توابع جستجوی فارسی.

> **چرا `pg_dump` و نه کپی جدول‌به‌جدول:** فقط `pg_dump` سازگاری ارجاعی و
> وضعیت توالی‌ها را حفظ می‌کند. پشتیبانی که توالی شماره ثبت را نداشته باشد،
> پس از بازیابی شماره‌های تکراری تولید می‌کند.

فایل با `--clean --if-exists` ساخته می‌شود، یعنی هنگام بازیابی، اشیای موجود
اول حذف می‌شوند. پس **بازیابی، جایگزینی کامل است، نه ادغام**.

نسخه مهاجرت (`schemaVersion`) در کنار هر پشتیبان ثبت می‌شود تا معلوم باشد
فایل مربوط به کدام نسخه ساختار پایگاه داده است.

---

## پشتیبان‌گیری دستی

**مدیریت ← پشتیبان‌گیری ← ایجاد پشتیبان جدید**

پس از ساخت، فهرست پشتیبان‌ها حجم، چک‌سام، نسخه ساختار و **وجود فیزیکی فایل**
را نشان می‌دهد. رکوردی که فایلش از روی دیسک پاک شده، «قابل بازیابی» علامت
نمی‌خورد.

هر پشتیبان قابل **دانلود** است. دانلود و نگهداری بیرون از سرور، مهم‌ترین کاری
است که می‌توانید بکنید.

---

## پشتیبان‌گیری خودکار

هر شب ساعت ۲ بامداد بررسی می‌شود و بر اساس تنظیمات عمل می‌کند:

| تنظیم | پیش‌فرض | معنی |
|-------|---------|------|
| زمان‌بندی | روزانه | `خاموش` / `روزانه` / `هفتگی` (جمعه‌ها) |
| تعداد نگه‌داشته‌شده | ۱۴ | پشتیبان‌های قدیمی‌تر خودکار پاک می‌شوند |
| شامل فایل‌های پیوست | بله | تصاویر جلد و پیوست‌ها |

تنظیمات ← پشتیبان‌گیری.

---

## بازیابی

**عملیات بازیابی برگشت‌ناپذیر است و داده فعلی را بازنویسی می‌کند.**

سامانه چهار محافظ دارد:

۱. **تأیید متنی.** باید عبارت `RESTORE` را دقیقاً تایپ کنید. کلیک اشتباهی
   کافی نیست.
۲. **بررسی چک‌سام.** اگر فایل روی دیسک با چک‌سام ثبت‌شده نخواند، بازیابی
   انجام نمی‌شود. فایل خراب نباید روی داده سالم بریزد.
۳. **پشتیبان ایمنی خودکار.** درست پیش از بازنویسی، از وضعیت فعلی یک پشتیبان
   گرفته می‌شود و شناسه‌اش در پاسخ برمی‌گردد. اگر بازیابی اشتباه بود، همان
   را برگردانید.
۴. **ثبت در Audit Log.** چه کسی، چه زمانی، از کدام فایل، و شناسه پشتیبان
   ایمنی.

پس از بازیابی، تنظیمات درون‌حافظه‌ای دوباره از پایگاه داده خوانده می‌شوند.

### بازیابی از خط فرمان

اگر سامانه بالا نمی‌آید و باید از بیرون بازیابی کنید:

```bash
# سرویس‌های وابسته را متوقف کنید تا کسی هم‌زمان ننویسد
docker compose stop api web

gunzip -c darin-2026-08-28T15-12-43.sql.gz \
  | docker compose exec -T postgres psql -U darin -d darin -v ON_ERROR_STOP=1

docker compose start api web
```

`ON_ERROR_STOP=1` مهم است: بدون آن `psql` با وجود خطا ادامه می‌دهد و پایگاه
داده نیمه‌بازیابی‌شده باقی می‌ماند.

## نگهداری بیرون از سرور

پشتیبانی که روی همان دیسک پایگاه داده است، در برابر خرابی دیسک، پاک شدن
تصادفی حجم Docker، یا از دست رفتن کل سرور بی‌فایده است.

نمونه انتقال شبانه به سرور دیگر:

```bash
# /etc/cron.d/darin-offsite
30 3 * * * root rsync -az --delete \
  /var/lib/docker/volumes/darin_api-storage/_data/backups/ \
  backup@backup-host:/srv/darin-backups/
```

مسیر دقیق حجم را با `docker volume inspect darin_api-storage` ببینید.

## تمرین بازیابی

**پشتیبانی که بازیابی‌اش را امتحان نکرده‌اید، پشتیبان نیست.** سالی دو بار،
روی یک پایگاه داده جداگانه امتحان کنید:

```bash
# ۱. پایگاه داده موقت
docker compose exec postgres createdb -U darin darin_restore_drill

# ۲. بازیابی در آن
gunzip -c <آخرین-پشتیبان>.sql.gz \
  | docker compose exec -T postgres psql -U darin -d darin_restore_drill -v ON_ERROR_STOP=1

# ۳. بررسی عددها — باید با سامانه زنده بخواند
docker compose exec postgres psql -U darin -d darin_restore_drill -c \
  "SELECT (SELECT count(*) FROM books)       AS books,
          (SELECT count(*) FROM book_copies) AS copies,
          (SELECT count(*) FROM members)     AS members,
          (SELECT count(*) FROM loans
            WHERE status IN ('ACTIVE','OVERDUE')) AS open_loans;"

# ۴. پاک کردن
docker compose exec postgres dropdb -U darin darin_restore_drill
```

اگر عددها خواندند، پشتیبان سالم است.

## عیب‌یابی

| نشانه | علت | راه حل |
|-------|-----|--------|
| «اجرای pg_dump ممکن نشد» | `postgresql-client` نصب نیست | تصویر API را دوباره بسازید، یا `PG_DUMP_PATH` را تنظیم کنید |
| فایل پشتیبان خیلی کوچک است | `pg_dump` نیمه‌کاره تمام شده | سامانه خودش این حالت را تشخیص می‌دهد و پشتیبان را ناموفق ثبت می‌کند؛ Log را ببینید |
| «چک‌سام مطابقت ندارد» | فایل هنگام کپی یا روی دیسک خراب شده | از نسخه بیرونی استفاده کنید |
| پشتیبان‌گیری خودکار اجرا نمی‌شود | زمان‌بندی روی «خاموش» است | تنظیمات ← پشتیبان‌گیری |
| دیسک پر می‌شود | تعداد نگه‌داشته‌شده زیاد است | مقدار را کم کنید؛ قدیمی‌ها خودکار پاک می‌شوند |
